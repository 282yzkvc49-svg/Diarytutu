# Правила для Codex: PWA «Дневник»

Это рабочее приложение v1.0.0 с данными пользователя на его устройствах. Задача — развивать и чинить его, а не переписывать. Полное ТЗ — в `SPEC.md`.

## Жёсткие правила

1. **Не терять данные.** Пользователь хранит дневник за годы только в IndexedDB на iPhone и iPad. Меняешь форму данных — подними `SCHEMA_VERSION` и добавь шаг в `migrateData()`; меняешь хранилища или индексы — подними `DB_VERSION` и дополни `onupgradeneeded`, проверяя `oldVersion`. Никогда не удаляй и не переименовывай поля без миграции.
2. **Совместимость копий.** Старые архивы `diary-*.zip` (format 1) должны импортироваться и дальше. Если меняешь `data.json` — подними `format` и поддержи чтение старого.
3. **Версия при каждом изменении:** `CACHE` в `sw.js` (`diary-v1` → `diary-v2`) и `APP_VERSION` в `index.html`. Иначе iOS покажет старую версию из кеша.
4. **Плоская структура.** Все файлы в корне, без папок — пользователь загружает их на GitHub с iPad по одному. Пути только относительные (`sw.js`, а не `/sw.js`).
5. **Без зависимостей.** Никаких фреймворков, сборщиков, CDN, внешних шрифтов и запросов в сеть: приложение работает офлайн. Весь код — в `index.html`.
6. **Никаких личных данных в репозитории.** Репозиторий публичный; записи живут только на устройстве.
7. **Даты** — только локальные строки `YYYY-MM-DD` через `ymd()` / `todayStr()`; не используй `toISOString()` для дат.
8. **Пользовательский текст** вставляется в DOM только через `textContent` (хелпер `h()` делает это сам). `innerHTML` — только для статичных иконок.

## Карта `index.html`

Скрипт идёт одним блоком, по разделам (ищи заголовки-комментарии `/* ===== ... ===== */`):

| Раздел | Что внутри |
| --- | --- |
| Настройки приложения | `APP_VERSION`, `DB_VERSION`, `SCHEMA_VERSION`, шкала `MOODS`, эмоции и факторы по умолчанию |
| Утилиты | `h()` / `put()` для DOM, иконки, даты, склонения (`plural`), `toast` |
| IndexedDB, Состояние | `openDB`, `idb.*`, `loadAll`, `migrateData`, `saveEntry`, `deleteEntry`, `mergeInto` |
| Медиа | уменьшение фото, превью видео, голос (`MediaRecorder`) |
| ZIP, Резервная копия | свой ZIP с CRC32, `exportArchive`, `importFile`, `mergeImport` |
| PIN-код | `hashPin` (SHA-256 с солью) |
| Интерфейс | вкладки `renderToday`, `renderEntries`, `renderCalendar`, `renderStats`; лист записи `renderEntryView` / `renderEditorInto`; настройки `renderSettings`; экспорт/импорт |
| Аналитика | SVG-графики `lineChart`, `barChart`, `devChart`, строки влияния `divRows` |
| Демо-данные | генератор примеров в отдельной базе `diary-demo` |
| Запуск | блокировка при возврате из фона, service worker, `init()` |

Цвета — CSS-переменные в `:root` (светлая и тёмная тема), шкала настроения — `--m1` … `--m7`.

## Как проверить

1. `python3 -m http.server 8000` в папке и открыть `http://localhost:8000/` (service worker работает на localhost).
2. Настройки → «Открыть демо» — три года примеров для проверки ленты, календаря и аналитики. Выход из демо удаляет только демо-базу.
3. Пройти критерии приёмки из `SPEC.md`, раздел 12: ширина 320 px, iPad в альбомной ориентации, тёмная тема, экспорт → импорт в другом профиле браузера, повторный импорт без дублей.
4. В консоли не должно быть ошибок.

## Стиль интерфейса

Русский язык, простые глаголы, без канцелярита. Кнопка называет действие («Сохранить файл», а не «ОК»). Ошибки говорят, что случилось и что делать. Цели касания не меньше 44 pt, поля ввода не меньше 16 px.
